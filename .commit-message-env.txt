Add .env loader for worker + llm entry points

Worker and LLM doctor scripts run via tsx and previously only saw env
vars that the user had exported into the shell. Prisma's internal env
loader only handles its own DATABASE_URL/DIRECT_URL keys — it does not
populate arbitrary application config (LLM_PROVIDER, EMBEDDING_PROVIDER,
RERANK_PROVIDER, VOYAGE_API_KEY, etc).

Until now, editing those keys in .env silently had no effect on the
running worker, and the matcher quietly fell back to provider defaults.
The defaults happened to match the previous "all Ollama" .env so nobody
noticed; switching to Voyage embeddings + reranker made the gap visible
(the worker kept stamping ollama:mxbai-embed-large despite the new
config).

This commit adds a pure-Node loader (no new deps) and wires it as the
very first side-effect import of every relevant entry:

  worker/src/util/load-env.ts            — shared loader for the worker
  packages/llm/src/util/load-env.ts      — same, used by the doctor CLI

  Wired into:
    worker/src/match-runner.ts
    worker/src/ingest-runner.ts
    worker/src/digest-runner.ts
    worker/src/eval-runner.ts
    worker/src/cron.ts
    packages/llm/src/doctor.ts

The loader:
  - walks up from cwd up to 6 levels looking for a .env file
  - parses simple KEY=VALUE and KEY="VALUE" lines
  - strips trailing `# comment` only when the value isn't quoted
  - preserves any var already set in the calling shell (standard
    "real env wins over .env" semantics, as in dotenv / docker / CI)
  - prints "[env] loaded N vars from <path>" when DEBUG_ENV is set,
    silent otherwise

Verified: with .env pointing at Voyage, the worker now stamps
voyage:voyage-4-large and rerank=voyage, retrievers return
sources=dense+text candidates with real cosine similarities.
